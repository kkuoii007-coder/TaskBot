## Описание продукта

**TaskBot** — Telegram-бот для небольших команд (до 50 человек), позволяющий:
- Добавлять задачи с приоритетом, дедлайном и исполнителем
- Отслеживать статус каждой задачи (новая → в работе → выполнена)
- Просматривать личные и командные задачи
- Экспортировать задачи в CSV
- Получать уведомления о приближающихся дедлайнах

Целевая аудитория — небольшие рабочие группы, стартапы, фрилансеры с командой.

## База данных

### Таблица `tasks`

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    text        TEXT NOT NULL,                        -- Текст задачи
    user        TEXT NOT NULL,                        -- @username создателя
    user_id     INTEGER NOT NULL,                     -- Telegram ID создателя
    assignee    TEXT,                                 -- @username исполнителя (необязательно)
    status      TEXT NOT NULL DEFAULT 'new',          -- new | in_progress | done | cancelled
    priority    TEXT NOT NULL DEFAULT 'medium',       -- low | medium | high
    deadline    TEXT,                                 -- Дата дедлайна YYYY-MM-DD (необязательно)
    created_at  TEXT NOT NULL,                        -- ISO 8601 datetime
    updated_at  TEXT NOT NULL                         -- ISO 8601 datetime (обновляется при изменении)
);
```

### Индексы (производительность)

```sql
CREATE INDEX IF NOT EXISTS idx_tasks_status ON tasks(status);
CREATE INDEX IF NOT EXISTS idx_tasks_user_id ON tasks(user_id);
CREATE INDEX IF NOT EXISTS idx_tasks_deadline ON tasks(deadline);
```

## Команды бота (полный список)

| Команда | Описание |
|---|---|
| `/start` | Приветствие, регистрация пользователя, показ главного меню |
| `/help` | Список всех команд с описанием |
| `/add` | Добавить задачу (через FSM-диалог с шагами) |
| `/list` | Все активные задачи команды (статус не `done`/`cancelled`) |
| `/my` | Задачи, созданные текущим пользователем |
| `/done [id]` | Пометить задачу как выполненную |
| `/cancel [id]` | Отменить задачу |
| `/status [id]` | Изменить статус задачи через inline-кнопки |
| `/delete [id]` | Удалить задачу (только автор или в течение 1 часа) |
| `/list_csv` | Получить все задачи файлом CSV |

## Сценарий FSM для `/add` (обязательный)

Команда `/add` должна работать через **Finite State Machine** с пошаговым диалогом:

1. **Шаг 1** — бот спрашивает: *«Введите текст задачи:»*
2. **Шаг 2** — бот спрашивает: *«Укажите приоритет:»* → **inline-кнопки**: 🔴 Высокий | 🟡 Средний | 🟢 Низкий
3. **Шаг 3** — бот спрашивает: *«Укажите дедлайн (ГГГГ-ММ-ДД) или нажмите «Пропустить»:»* → **inline-кнопка** «Пропустить»
4. **Шаг 4** — бот спрашивает: *«Укажите исполнителя (@username) или нажмите «Пропустить»:»* → **inline-кнопка** «Пропустить»
5. Задача сохраняется в БД, бот выводит карточку задачи с подтверждением

## Планировщик напоминаний (reminders.py)

- Запускается при старте бота
- Каждый день в **09:00** проверяет задачи, у которых дедлайн **сегодня или завтра** и статус не `done`/`cancelled`
- Отправляет напоминание в чат создателю задачи:
  ```
  ⏰ Напоминание!
  Задача #15 «Подготовить презентацию» истекает завтра (24.06.2026)
  ```

## Ограничения и важные правила

- **Не использовать** ORM (SQLAlchemy, Tortoise и др.) — только чистый `sqlite3` / `aiosqlite`
- **Не использовать** сторонние state-машины — только встроенная `FSMContext` из `aiogram`
- **Не добавлять** избыточный функционал (авторизация, роли пользователей, web-панель) — только то, что описано
- **Не нарушать** структуру пакетов: весь SQL только в `database/queries.py`
- **Подождать** и показать план архитектуры перед началом кодирования, получить одобрение
